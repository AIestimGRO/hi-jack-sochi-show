# HI, JACK — HI, SOCHI SHOW

Отдельное веб-приложение для турнира 7 ноября 2026. **Не является модулем JACKSIDE и не зависит от Hi Jack Timer.**

## Схема

```
JACKSIDE (8090 PROD, 8091 staging)   Hi Jack Timer (существующий сервис)
                  \                          /
                   [ НЕ ИСПОЛЬЗУЮТСЯ ]
                              |
SOCHI SHOW: самостоятельный FastAPI / localhost:8092
 ├─ /sochi/admin                 закрытая админка с сессионным входом + CSRF
 ├─ /sochi/screen                публичный проектор
 ├─ /sochi/api/admin/*           закрыто: черновики, места, фото, роли
 ├─ /sochi/api/public/state     только опубликованный snapshot
 ├─ /sochi/api/public/events    SSE, только опубликованный snapshot
 ├─ data/sochi.sqlite3          отдельная база, только этого шоу
 └─ data/media/                 отдельные подготовленные фотографии
```

Существующие базы `club_tools.sqlite3` и данные таймера **не используются**, их миграция и рестарт не требуются. Отдельная авторизация организатора на основе переменных окружения. Публичное состояние замораживается при публикации; при вводе в черновик экран не меняется. При SSE-reconnect восстанавливается текущая сцена. Публичный доступ к картинкам закрыт до фактической публикации конкретного игрока.

## Что уже реализовано

- Импорт `hi_jack_sochi_seating_v2.json`, исключительно `variants["10"]`, `["11"]`, `["12"]`, `["13"]`, проверка уникальности мест/карт, разных столов одной команды, распределения 10/10/10, 8/8/8/9, 9/9/9/9, 10/10/10/9. **В комплект включена восстановленная из ранее загруженного файла рассадка**; перед выдачей настоящих карточек организатор сверяет места с утверждённым первоисточником. Новая жеребьёвка не создаётся автоматически.
- Настройка команд и привязка имён игроков к карточкам. Для переключения после привязки требуется отдельное подтверждение физических карточек; после публикации результатов смена набора заблокирована.
- Редактирование `display_name` при неизменных `team_id` и `original_name`, отдельная публикация каждого имени.
- Капитаны из трёх игроков команды; загрузка фотографий каждого игрока (JPEG/PNG/WEBP), серверная обработка Pillow, JPEG/PNG/WEBP → WEBP 560x560 без исходного EXIF, лимит 5 МБ.
- GREEN, BLUE, RED с целочисленным счётом, нулевыми и отрицательными очками; BLUE использует зафиксированный фактический GREEN-стек, не GREEN-очки. Отдельное сохранение черновика, массовый ввод и публикация.
- Три Secret Jacks, отдельное приватное назначение, кто первый выбил, команда и контроль +10 000 на карточку. Пошаговая публикация по одной карте, исправление после раскрытия с пересчётом без повторного начисления.
- Голоса по принципу одна команда → другая, +10 000 голосующей или выбранной по зафиксированной настройке. До команды организатора не доступны публично.
- Реальное замороженное состояние публикации, предварительные рейтинги, журнал действий, возможность вернуться на любую уже доступную сцену, заставка, команды, GREEN/BLUE/RED, капитаны, Secret Jacks, голоса, финал и победитель, пауза, CSV.
- Админка только через серверный вход; Secure/HttpOnly/SameSite cookies, CSRF для всех записей, проверка Origin, ограничение попыток входа на IP.

## Известные ограничения текущей итерации

Это **проверяемый автономный рабочий MVP**, а не полностью прошедший репетицию проекторный релиз. Перед прямым эфиром требуется сверить восстановленную рассадку с исходным утверждённым `hi_jack_sochi_seating_v2.json`, импортировать подтверждённый файл через админку, провести прогон со всеми командами и проверить фактический экран 1920x1080. Оригинальный фирменный векторный логотип уже встроен; никаких вымышленных фото нет. Анимации базовые CSS, не полная продакшен-постановка с интерактивными таймлайнами. Нет интеграции с JACKSIDE/таймером по замыслу.

Отдельно: нельзя публиковать сгенерированные `examples/` тестовые карточки как действительную рассадку.

## Локально / отдельный staging без вмешательства в другие сервисы

```bash
python3 -m venv .venv
.venv/bin/pip install -r requirements-dev.txt
cp .env.example .env
# Сгенерируйте ДВА отдельных значения:
openssl rand -hex 32  # SOCHI_ADMIN_PASSWORD
openssl rand -hex 32  # SOCHI_SESSION_SECRET
# Впишите в .env; на локальном HTTP SOCHI_SECURE_COOKIE=false
set -a; source .env; set +a
.venv/bin/pytest -q
.venv/bin/uvicorn sochi_show.server:app --host 127.0.0.1 --port 8092
```

В локальном браузере:
- `http://127.0.0.1:8092/sochi/admin`
- `http://127.0.0.1:8092/sochi/screen`
- `http://127.0.0.1:8092/health`

Для HTTPS **обязательно** `SOCHI_SECURE_COOKIE=true`. Не включайте публикацию админки в открытый HTTP. На сервере без новых правил Nginx доступ только через SSH-tunnel: `ssh -L 8092:127.0.0.1:8092 <user>@<host>` (порт приложения не публикуется наружу).

## Схема таблиц

`settings`, `teams`, `seats`, `players`, `stages`, `secrets`, `votes`, `publication`, `audit`.

`publication.payload` — только публикуемый снимок, с отдельными внутренними полями фактического GREEN-стека. В публичных эндпоинтах эти внутренние поля вырезаются. Данные Secret Jack/голосов не попадают в `publication` до нажатия «Раскрыть». Пути фото относятся только к собственному медиа-каталогу.

## Тест на проекторе и репетиция

1. Войти по отдельному паролю, импортировать **официальный** JSON и выбрать 10/11/12/13.
2. Проверить распределение 10/10/10 (для 10 команд стол №4 отсутствует), физические места и три разных стола для каждой команды.
3. Назначить 3 игроков в каждой команде, капитана, фотографию капитана и любого другого игрока; проверить фото и нейтральный аватар.
4. Переименовать команду после GREEN: до команды «В эфир» название на проекторе должно оставаться прежним.
5. GREEN: заполнить `green_stack`, `reentry_chips`, `reentry_count`; проверить отрицательные значения.
6. BLUE: заполнить фактический `blue_stack`, `addon_chips`, `survivors`, убедиться, что не вычтены re-entry второй раз.
7. RED: сохранить уникальные итоговые места; при 11–13 командах провести внешний регламент капитанского стола.
8. Назначить 3 Secret Jacks (в том числе не капитана); до раскрытия открыть DevTools и проверить `/sochi/api/public/state` и SSE.
9. Открыть три Jack по одному, повторно нажать открытие — должен прийти 409; исправить раскрытую карточку и проверить отсутствие двойных баллов.
10. Проголосовать каждой командой за другую, открыть голоса только по кнопке; проверить 10 000 за каждый голос.
11. Обновить страницу проектора посередине сцены, отключить соединение, проверить последний кадр; запустить полный экран.
12. Проверить 13 команд на 1920x1080, длинные имена и ничью; скачать протокол CSV.

## Безопасный rollback

Не выполняйте `git pull`/`systemctl restart` для существующих сервисов Hi Jack Timer или JACKSIDE. У этого проекта отдельный путь, база и unit. Для отката собственного релиза остановите **только** `sochi-show.service`, восстановите собственные `data/sochi.sqlite3` и `data/media` из отдельной копии, затем запустите **только** `sochi-show.service`. Даже полный откат SOCHI SHOW не меняет ни одного файла рабочих приложений.

## Фирменные материалы и рассадка

В `sochi_show/static/hi-jack-logo.svg` встроен предоставленный организатором оригинальный SVG. В `examples/hi_jack_sochi_seating_v2.json` сохранена структурно эквивалентная копия рассадки, восстановленная из полного индексированного текста ранее загруженного оригинала: 13 команд, исходные 39 карточек, готовые схемы 10/11/12/13 на 30/33/36/39 мест. Проведена проверка числа мест, трёх разных столов на команду и отсутствия пересечений. Исходные байты старого файла из библиотеки недоступны, поэтому перед фактической раздачей конвертов организатор должен сверить карточки с утверждённым первоисточником. Секретные роли в этом JSON отсутствуют.
